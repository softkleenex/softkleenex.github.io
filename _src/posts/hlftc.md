이 프로젝트는 `한화생명 미래금융인재 공모전` AI 분야에 제출하기 위해 만든 `LifeTwin AI` 기획안 기록이다. 일반적인 Kaggle/DACON 모델링 대회와 달리, 이 작업의 중심은 코드가 아니라 문제 정의, 시장 근거, 서비스 설계, 발표 자료였다.

아이디어의 한 줄 요약은 이렇다.

> 나의 건강이 변하면, 나의 금융도 함께 진화한다.

한화생명의 기존 건강관리 앱 `HELLO`를 고도화해 건강 데이터와 금융 마이데이터를 결합하고, 고객의 생애주기와 건강 리스크를 반영하는 디지털 트윈 기반 자산관리 플랫폼을 제안했다.

## 문제 정의

기획의 출발점은 기존 금융 서비스가 건강 변화를 충분히 반영하지 못한다는 점이었다. 자산관리 서비스는 위험 성향 설문이나 금융 자산 중심으로 움직이고, 헬스케어 서비스는 활동량이나 건강 미션 중심으로 움직인다. 하지만 실제 사람의 삶에서는 건강 변화가 의료비, 보험, 은퇴 시점, 연금 수령 전략에 직접 영향을 준다.

그래서 LifeTwin AI는 세 가지를 묶으려 했다.

| 축          | 내용                                               |
| ----------- | -------------------------------------------------- |
| 건강 데이터 | HELLO 앱, 웨어러블, 건강검진, 의료 마이데이터      |
| 금융 데이터 | 은행, 카드, 보험, 퇴직연금, 투자 자산              |
| AI 엔진     | 디지털 트윈, What-if 시뮬레이션, 포트폴리오 최적화 |

핵심은 "건강이 좋아지면 보험료와 금융 전략도 달라지고, 건강 리스크가 커지면 자산 배분과 보장 전략도 바뀌어야 한다"는 구조였다.

## 근거 만들기

이 작업에서 중요했던 건 그럴듯한 아이디어를 쓰는 것이 아니라, 숫자와 사례로 설득력을 만드는 일이었다. 그래서 `FACT_CHECK_REPORT.md`를 따로 만들고, 시장 규모와 벤치마크 수치를 검증했다.

확인한 근거는 대략 다음과 같았다.

- 퇴직연금 시장: 2024년 `432조원`, 2034년 `1,034조원` 전망
- 웨어러블 시장: 2025년 `$66.45B`, 2033년 `$528.58B` 전망
- 의료 마이데이터: 2025년 상반기 상급종합병원 연동 흐름
- John Hancock Vitality: 고혈압 정상화 `52%`, 고콜레스테롤 정상화 `63%`, 보험료 절감 회원 약 `90%`
- 한화생명 자산: HELLO 앱, AI 조직, HAC, 스탠포드 HAI 협력, 차바이오 협력

사실 검증을 한 번 거치니 기획안의 톤이 달라졌다. "이런 서비스가 있으면 좋겠다"에서 "이 시장과 회사 자산을 보면 이런 서비스가 말이 된다"로 바뀌었다.

## 솔루션 구조

제안한 플랫폼은 네 개 layer로 구성했다.

1. Data Integration: 금융 마이데이터와 건강 데이터를 합친다.
2. Digital Twin Engine: 건강-금융-생활 통합 고객 모델을 만든다.
3. AI Decision Engine: SAC 강화학습 포트폴리오 최적화와 RAG 기반 상품 추천을 붙인다.
4. Service Output: PAYL 보험, 퇴직연금 최적화, 생애주기 리포트로 고객에게 돌려준다.

기술 이름을 나열하는 것보다 중요한 건 사용자가 이해할 수 있는 시나리오였다. 예를 들어 고혈압 진단이 나오면 의료비 리스크와 보장 필요성이 바뀌고, 건강 습관이 개선되면 보험료 할인과 연금 전략이 함께 조정되는 식이다.

## 만든 산출물

이 프로젝트는 코드 repo라기보다 제출 패키지에 가까웠다.

| 산출물                   | 역할                          |
| ------------------------ | ----------------------------- |
| `IDEA_LifeTwin_AI_v2.md` | 기획안 본문과 기술/시장 근거  |
| `PPT_CONTENT_FINAL.md`   | 20장 분량 슬라이드별 메시지   |
| `FACT_CHECK_REPORT.md`   | 수치와 주장 검증              |
| 제출 PDF                 | 공모전 제출용 완성본          |
| `VIDEO_SCRIPT.md`        | 4분 내외 pitch video 스크립트 |
| visualization images     | 시장/아키텍처/로드맵/ROI 차트 |

이 과정은 "기획도 엔지니어링처럼 관리할 수 있다"는 감각을 줬다. 자료 수집, 출처 검증, 슬라이드 메시지, 발표 스크립트, 제출 양식이 따로 놀면 마지막에 무너진다. 그래서 문서별 역할을 나누고, 제출용 폴더와 참고자료 폴더를 분리했다.

## 아쉬운 점

가장 큰 아쉬움은 실제 prototype까지 가지 못했다는 점이다. 아이디어는 충분히 구체적이었지만, 데모 앱이나 간단한 시뮬레이터가 있었다면 훨씬 강해졌을 것이다.

다시 한다면 다음을 추가하고 싶다.

1. 건강 점수 변화에 따른 보험료/포트폴리오 변화 mock dashboard
2. synthetic user profile 3개로 생애주기 What-if simulation
3. HELLO 앱 연계 화면을 가정한 clickable prototype
4. SAC 포트폴리오 최적화는 실제 수식보다 시각적 전후 비교 중심으로 설명
5. 공모전 제출 후에도 GitHub 공개용 sanitized repo로 정리

기획안은 모델 학습 결과처럼 숫자로 바로 평가되지 않는다. 대신 얼마나 많은 반론을 미리 막았는지가 품질이 된다. 이 프로젝트에서는 fact check와 발표 스크립트까지 함께 남긴 것이 가장 좋은 결정이었다.
